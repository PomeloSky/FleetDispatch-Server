# 稽核紀錄與修改前後歷史

主機有兩種紀錄：

| | 稽核紀錄（`fd_audit`，1.0 起） | 修改前後歷史（`fd_record_history`，1.2.0 起） |
| --- | --- | --- |
| 內容 | 誰（裝置）在何時對哪筆資料做了什麼；內容摘要（前 2,000 字元） | 修改前與修改後的完整內容、變更的欄位、來源、身分、原因、序號、版本 |
| 用途 | 快速查看最近的操作 | 追查一筆資料的完整變化、還原時參考 |
| API | `GET /admin/audit` | `GET /admin/history?entity=&id=` |
| 誰能看 | 管理員 | 管理員 |

## 修改前後歷史的欄位

| 欄位 | 說明 |
| --- | --- |
| `at` | 主機時間（毫秒） |
| `entity`、`entity_id` | 資料的種類與 UUID |
| `event_id` | App 事件的 ID（連鎖刪除等沒有事件時為 null） |
| `operation` | `create`、`update`、`delete` |
| `source` | `app`（App 的事件）、`cascade`（刪除車輛的連鎖刪除）；`web`（網頁管理的修改）與 `api` 保留給之後的管理功能 |
| `actor_device`、`actor_identity`、`actor_name` | 寫入者的裝置 ID、這次配對的主機端身分、裝置名稱 |
| `before_json`、`after_json` | 修改前、修改後的內容（新增時沒有修改前，刪除時沒有修改後）。修改前的內容在寫入的同一個交易中讀取 |
| `changed_fields` | 變更的第一層欄位（不含 `lastModifiedAt`） |
| `reason` | 原因（連鎖刪除是 `vehicle-deleted`） |
| `seq`、`revision` | 這次寫入取得的序號與資料的版本 |

規則：

- 與資料在同一個交易寫入：資料有改，歷史一定有；沒有寫入（被拒絕、最後寫入者勝略過、衝突）就沒有歷史。
- 只新增、不修改：舊紀錄不會被覆寫。
- 重送同一個事件（冪等）不會產生第二筆。

## 個資

歷史保存完整的內容，駕駛人的證號、電話、備註也在其中，所以只給管理員查看；主機不把歷史送到 App。

## 保留期限

1.2.0 不自動刪除歷史（車隊的資料量小，完整保存較安全）。若需要依公司規定設定保留期限，可直接以 SQL 刪除較舊的紀錄，例如保留兩年：

```sql
DELETE FROM fd_record_history WHERE at < <兩年前的毫秒時間>;
```

已處理事件（`fd_processed_events`）自動保留 30 天。
